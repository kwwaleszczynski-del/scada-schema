# scada-schema specification, version 1.0

Generated by `scada-schema spec` from the code; do not edit by hand. The wording "must" and "may" is used as in RFC 2119.

## The table

A canonical table is a data frame (stored as Parquet) with one row per device and interval.

* `timestamp`: `datetime64[ns, UTC]`, the **start** of the averaging interval. Rows must be on the interval grid (the interval is one of 5min, 10min, 15min, 30min, 1h).
* `device_id`: text, unique within the dataset; the device types are `turbine`, `inverter`, `string`, `met`, `meter`, `plant`.
* signal columns: the canonical names of the tables below, in the canonical unit, as `float32` (`float64` for energies and meter readings). Text signals (`status_code`) and categories (`iec_category`) are `object` columns of `str` or `None`.
* statistics: where a source logs them, the minimum, maximum and standard deviation of an interval are the columns `<signal>__min`, `<signal>__max`, `<signal>__std`, allowed for the signals marked in the tables.
* extension columns start with `x_` and are not validated beyond their key.
* rows are sorted by `(device_id, timestamp)`; the pair is unique.

Missing values are `NaN` (or `None` for text). A signal that a device does not have is absent for that device (all `NaN`), not zero. A column that no device has is omitted.

## Conventions

* **Time.** UTC, interval start. A source that stamps the end or the centre of its interval, or uses local time, is converted by the loader; the convention of the *source* is kept in the metadata (`source_timezone`, `source_label`) so that the conversion is auditable. Local time with daylight saving is resolved by order of appearance in the repeated autumn hour; stamps that cannot be placed become missing rows, not shifted ones.
* **Power and energy** are positive when they flow out of the asset into the grid; consumption is negative.
* **Angles** are degrees. Compass angles run clockwise from true north. A wind direction is the direction the wind comes **from**; `nacelle_dir` is the position of the nacelle, clockwise from true north (a source that references another north is corrected by its loader or flagged by the `wind_direction` check); `wind_dir_rel` is the vane reading relative to the nacelle.
* **Pitch** is 0 in the power position and about 90 degrees when feathered.
* **Energy** `e_export` is the energy in the interval (kWh), `e_export_counter` the cumulative meter reading (kWh).
* **Units** are SI-based: kW, kvar, kWh, V, A, rpm, m/s, W/m2, degC, Pa, %. Loaders convert; every conversion is listed in the metadata (`conversions`).

## Metadata

Stored in the Parquet key-value metadata under `scada_schema` as JSON (the `DatasetMeta` model): `schema_version`, `name`, `profile` (`wind` or `pv`), `interval`, `source_timezone`, `source_label`, `devices`, `source`, `conversions`, `notes`.

A device has: `id`, `type`, `rated_kw`, `capacity_kwp`, `lat`, `lon`, `hub_height_m`, `rotor_diameter_m`, `tilt_deg`, `azimuth_deg`, `parent`. A source has: `name`, `doi`, `url`, `license`, `citation`.

## Validation

`validate(df, meta)` returns every violation with a code and a count (see `scada_schema.validate` for the list). A table with an error must not be written by `write_parquet`.

## States and IEC 61400-26

`iec_category` takes one of ten categories (the top levels of the information model of IEC 61400-26-1, as used by `res_asset_kpi`; the standard's tree is finer and its definitions and their contractual use must be checked against the standard and the contract):

| category | meaning |
|---|---|
| `full_performance` | Full performance |
| `partial_performance` | Partial performance (technical derating) |
| `technical_standby` | Technical standby |
| `environmental` | Out of environmental specification |
| `requested` | Requested shutdown or curtailment (grid operator or owner) |
| `electrical` | Out of electrical specification (grid) |
| `scheduled_maintenance` | Scheduled maintenance |
| `planned_corrective` | Planned corrective action |
| `forced_outage` | Forced outage |
| `no_info` | Information unavailable |

Shipped code tables: `senvion_mm`, `siemens_swt_hot`; label tables: `greenbyte`, `care`. They were written from the public code texts of the open datasets and are a starting point, not an OEM document. An event labels an interval when the interval's midpoint lies in the event; where events overlap, the one that started last wins.

## Quality control

| check | question |
|---|---|
| `duplicates` | are there rows that repeat a (device, time stamp)? |
| `ordering` | are the rows in time order within a device? |
| `time_jumps` | do time stamps leave the interval grid or step by less than one interval? |
| `gaps` | how many intervals are missing between the first and the last time stamp? |
| `dst` | do gaps or repeats of an hour at the daylight saving changes show up? |
| `missing_values` | how much of each signal is empty? |
| `out_of_range` | values outside the hard physical limits of the signal (unit and scaling errors) |
| `flatline` | a sensor repeating one value for hours |
| `spikes` | single values far from their neighbours (Hampel filter) |
| `power_curve` | power far from the median power curve of the same turbine at that wind speed |
| `wind_direction` | vane, nacelle and absolute direction that do not add up; north offsets between turbines |
| `energy_counter` | meter readings that go backwards or jump; counter steps against interval energy |
| `energy_power` | interval energy against mean power times the interval length |
| `icing` | anemometer reading zero while the rotor turns in the cold; power loss in icing conditions |
| `units` | power of the wrong order of magnitude, a switch of unit within a record, hints of other units |
| `iec_category`) the checks use them; otherwise read the findings with the plant in mind. |  |

Default thresholds (`QCConfig`): spike filter window 7 intervals at 8 robust deviations; north offset reported above 10 degrees; icing below 3 degC; unit steps from 0.8 decades (1.5 in wind farms).

## Importing other data

`scada-schema import mapping.yaml` builds a canonical table from a CSV, Excel or Parquet export with a YAML mapping (see `scada_schema.loaders.generic`). JSON Schema files of the metadata and of the mapping and a list of all canonical columns are in `schema/` (`scada-schema jsonschema`).

## Resampling

`resample(df, meta, to)` goes to a longer interval that is a multiple of the source's. Rules by signal kind: mean; vector mean for angles; sum for energies; last reading for meter counters; most frequent value for status; minimum of minima and maximum of maxima; pooled standard deviation (mean of the variances plus variance of the means). A target interval needs at least 80 % of its source intervals (`min_coverage`) or it is missing.

## Versioning

The schema version is `1.0`. A new signal or profile is a minor version; a change of a unit, a sign or a name is a major version. Files carry the version they were written with.
